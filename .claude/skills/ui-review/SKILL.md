# 과제 리뷰

인자: `$ARGUMENTS` (예: `03` 또는 `03 answers`)

## 0. 시작 확인
- 이 세션에서 해당 과제를 구현한 기록이 보이면 중단하고 새 세션에서 실행하라고 안내한다.
- `docs/progress.md` 상태가 `제출됨`인지 확인한다.

## 1차 리뷰 (`/ui-review NN`)
1. 읽을 것: `docs/rubric.md`, `docs/curriculum.md`의 해당 Day "평가" 항목, `submissions/day-NN/submission.md`, `docs/matrix/`, 변경 내용(`git diff main...<제출 브랜치>`).
2. A. 자동 측정: `npm run check` 실행. 결과를 그대로 기록한다. Lighthouse 등 사용자가 준 수치는 "사용자 제공"으로 표시.
3. B. 채점: 해당 항목만 채점한다. 모든 점수에 근거(`파일:줄`, 테스트명, 측정값)를 붙인다. 근거가 없으면 "판단 불가".
4. 매트릭스와 코드가 다르면 반드시 지적한다 (매트릭스에 있는데 구현/테스트가 없는 행).
5. C. 본인 설명 질문 3개를 만든다.
   - 이번 과제 코드의 핵심 결정에 대한 질문 ("왜", "어디서", "만약 ~라면")
   - 코드를 외우는 질문이 아니라 이해를 확인하는 질문
   - 정답 예시는 쓰지 않는다
6. `templates/review-report.md`를 복사해 `reviews/day-NN.md`에 A, B, C(질문만)를 작성한다.
7. 안내: "코드를 보지 말고 `reviews/day-NN.md`의 '본인 답변'에 답을 적은 뒤 `/ui-review NN answers`를 실행하세요."

## 2차 리뷰 (`/ui-review NN answers`)
1. 답변을 질문별 5점으로 채점하고 코멘트를 단다. 틀린 부분은 무엇이 틀렸는지 구체적으로.
2. `docs/rubric.md` 방식으로 환산 점수와 판정(통과/재도전)을 계산한다.
3. "다음에 보완할 1가지"와 "CLAUDE.md에 추가 제안할 규칙"을 쓴다.
4. `docs/progress.md` 갱신: 일자별 기록, 상태(`통과`/`재도전`), 약점 누적, 재도전이면 보완 과제 1~2개.
5. 통과면 PR 병합을 안내한다 (병합은 사용자가 한다).

## 지킬 것
- 후하게 주지 않는다. 기준표에 없는 가산점은 없다.
- 개선점을 먼저, 구체적으로 쓴다.
- 코드를 직접 고치지 않는다. 리뷰만 한다.
