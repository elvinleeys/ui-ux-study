# 채점 기준표

## 항목 (100점)
| 코드 | 항목 | 배점 | 방식 | 만점 기준 |
|---|---|---|---|---|
| M | 상태·예외 매트릭스 완성도 | 15 | B | 상태 8종 + 해당 예외(중복 클릭, 실패, 극단 입력, 키보드)가 빠짐없고 기대 동작이 명확함 |
| T | 매트릭스대로 동작 | 20 | A | 매트릭스 행에 대응하는 테스트가 있고 모두 통과 |
| X | 접근성 | 15 | A+B | 키보드만으로 사용 가능, 포커스가 보임, 대비 확인 기록 있음 |
| P | 성능 | 10 | A | before/after 수치와 개선 이유 기록 |
| R | 토큰·코드 규칙 | 10 | A+B | 하드코딩 없음, 200줄 이내, 필요한 곳에만 주석 |
| F | 정답지 대비 정확도 | 10 | B | 비교 보드의 차이가 해소되었거나 남긴 이유가 있음, 출처 표기 완비 |
| E | 본인 설명 | 15 | C | 질문 3개에 코드 없이 정확히 답함 |
| L | 프롬프트·사용량 기록 | 5 | B | 핵심 프롬프트와 수정 이유, 사용량 메모 |

방식: A = 자동 측정(`npm run check` 등), B = 리뷰 세션 판단, C = 본인 설명

## 계산
- 그날 해당 없는 항목은 제외하고 100점으로 환산한다. (해당 항목은 `docs/curriculum.md`의 "평가" 참고)
- 환산 점수 = (받은 점수 합 ÷ 해당 항목 배점 합) × 100, 소수점 버림

## 판정
- **통과**: 환산 70점 이상 **그리고** 본인 설명(E) 60% 이상
- **재도전**: 위 조건 미달. 리뷰가 보완 과제 1~2개를 `progress.md`에 추가한다.

## 리뷰 원칙
- 모든 점수에 근거를 붙인다: `파일:줄`, 테스트 결과, 측정값 중 하나.
- 근거를 댈 수 없으면 0점 대신 "판단 불가"로 표시하고 이유를 쓴다. 판단 불가 항목은 환산에서 제외한다.
- 칭찬보다 개선점을 먼저, 구체적으로 쓴다.
