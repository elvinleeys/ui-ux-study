# 2주 커리큘럼 (사이클 1: GOV.UK Design System 정답지)

- 하루 기준: 최대 2시간. 1시간만 가능하면 Day 하나를 이틀에 나눠도 된다 (progress에 기록).
- 빠진 날은 몰아서 하지 않는다. 멈춘 Day부터 이어서 한다.
- 정답지: GOV.UK Design System (무료 오픈소스). 실제 컴포넌트 존재 여부는 Day 1에 목록 페이지에서 확인한다.
- GOV.UK에 없는 컴포넌트(모달 등)는 다른 공개 디자인 시스템에서 가져오되 라이선스를 확인한다.
- 정부 로고·브랜드 요소는 쓰지 않는다.
- 평가 항목 코드는 `docs/rubric.md` 참고.

---

## 1주차: 정적 정확도 + 상태

### Day 1. 준비
- 목표: 저장소와 검사 도구를 갖추고 대상 컴포넌트를 정한다.
- 할 일
  1. GOV.UK 컴포넌트 목록을 보고 대상 5개를 정한다: 버튼(CTA), 텍스트 입력, 에러 표시, 탭 또는 아코디언, 목록 화면용 요소.
  2. Claude Code로 Next.js(App Router) + TypeScript 프로젝트를 만든다.
  3. 검사 도구 설치: ESLint, stylelint(`color-no-hex` 등으로 컴포넌트 내 색 하드코딩 금지, `src/tokens/`는 예외), Playwright.
  4. `package.json`에 `"check": "npm run lint && npm run lint:css && node scripts/check-lines.mjs && npx playwright test"` 추가.
  5. `progress.md`에 시작일 기록.
- 산출물: 동작하는 빈 프로젝트, `npm run check` 실행 화면 캡처, 대상 컴포넌트 목록(+URL)
- 평가: R, L, E

### Day 2. 토큰 추출
- 목표: 타이포·색·간격 값을 출처와 함께 토큰으로 만든다.
- 할 일
  1. 공식 문서에서 값을 직접 찾아 기록한다 (Claude에게 값을 묻지 않는다).
  2. `src/tokens/`에 JSON 또는 CSS 변수로 정리. 값마다 출처 URL과 확인일.
  3. 글자색/배경색 대비를 계산해 기록한다 (기준은 WCAG 공식 문서 확인).
- 토큰 형식 예시: `{ "text-primary": { "value": "<측정값>", "source": "[공식] <URL>", "checked": "YYYY-MM-DD" } }`
- 산출물: `src/tokens/*`, 비교 보드 02 타이포·05 색·07 간격 초안
- 평가: F, R, E

### Day 3. CTA 버튼 — 상태 8종
- 목표: 매트릭스를 먼저 쓰고 버튼을 구현한다.
- 할 일
  1. `templates/state-matrix.md`를 복사해 `docs/matrix/button.md` 작성. Claude에게 초안을 받고 직접 확정.
  2. 상태 8종 + 크기 변형 구현. 터치 영역 크기는 공식 기준을 찾아 근거로 적는다.
  3. hover/focus-visible/disabled 테스트 작성.
- 산출물: 매트릭스, 버튼 컴포넌트, 테스트
- 평가: M, T, X, R, E, L

### Day 4. CTA 예외 처리
- 목표: 실제 장애로 이어지는 예외를 막는다.
- 할 일
  1. 가짜 제출 API를 만든다: 지연(예: 2초), 실패 확률, 시간 초과를 조절 가능하게.
  2. 더블클릭·Enter 연타 → 요청 1회, 실패 → 에러 표시 + 재시도, 시간 초과 처리.
  3. 매트릭스 예외 행 1~5를 테스트로 옮긴다.
- 산출물: 예외 테스트, 매트릭스 결과 열 채우기
- 평가: M, T, X, R, E, L

### Day 5. 텍스트 입력 + 폼 검증
- 목표: 에러를 언제, 어떻게 보여 줄지 결정하고 구현한다.
- 할 일
  1. 검증 시점(입력 중/포커스 이탈/제출 시)을 정하고 이유를 매트릭스 "결정 기록"에 쓴다.
  2. 에러 문구를 입력창과 연결(`aria-describedby`), 에러 시 포커스 이동 규칙 정하기.
  3. 빈 값, 붙여넣기, 아주 긴 값, 이모지 입력 확인.
- 산출물: `docs/matrix/text-input.md`, 컴포넌트, 테스트
- 평가: M, T, X, R, F, E, L

### Day 6. 탭/아코디언 키보드 조작
- 목표: 마우스 없이 쓸 수 있게 만든다.
- 할 일
  1. 정답지 문서에서 키보드 동작을 확인해 매트릭스에 적는다.
  2. Tab 순서, 방향키/Enter/Space 동작, focus-visible 구현.
  3. 키보드 시나리오 테스트 작성.
- 평가: M, T, X, R, E, L

### Day 7. 비교 보드 v1 + 회고
- 목표: 1주차 결과를 정답지와 대조하고 규칙을 정리한다.
- 할 일
  1. `submissions/day-07/board/`에 카테고리별 비교 페이지(타이포, 색, 간격, 상태): 정답지 / 내 구현 / 차이 / 조치.
  2. 어긋난 원인을 `CLAUDE.md` "학습으로 생긴 규칙"에 1~3줄 추가.
  3. 1주차 회고 (velog 초안 소재).
- 평가: F, R, E, L

## 2주차: 동적·예외·성능

### Day 8. 목록 화면 4상태
- 목표: 로딩/빈 화면/에러/부분 실패를 모두 설계한다.
- 할 일
  1. 가짜 목록 API(지연, 빈 배열, 실패, 일부 항목만 실패).
  2. 스켈레톤 로딩, 빈 화면 안내+CTA, 에러+재시도, 부분 실패 표시.
  3. 상태별 테스트.
- 평가: M, T, X, R, E, L

### Day 9. 모션
- 목표: 모션을 토큰으로 관리하고 접근성을 지킨다.
- 할 일
  1. 지속 시간·easing 토큰 정의 (정답지에 없으면 `[추정]` + 이유).
  2. 버튼 피드백, 아코디언 열림, 목록 등장에 적용. `transform`/`opacity` 위주.
  3. `prefers-reduced-motion` 대응 + 테스트.
- 산출물: 모션 토큰, 비교 보드 09 모션
- 평가: M, T, X, R, F, E, L

### Day 10. 모달(또는 드로어)
- 목표: 가장 예외가 많은 인터랙션을 완성한다.
- 할 일
  1. 정답지를 고르고 라이선스 확인.
  2. 포커스 트랩, Esc 닫기, 배경 스크롤 잠금, 닫은 뒤 포커스 복귀, 바깥 클릭 정책 결정.
  3. 시나리오 테스트.
- 평가: M, T, X, R, E, L

### Day 11. 극단 환경 테스트
- 목표: 깨지는 지점을 찾아 고친다.
- 할 일
  1. 긴 텍스트, 폭 320px, 200% 확대, 가로 모드.
  2. 개발자 도구 Network 속도 제한, 오프라인.
  3. 깨진 지점 목록 → 수정 → 스크린샷 before/after.
- 평가: T, X, R, E, L

### Day 12. 성능
- 목표: 수치로 개선을 증명한다.
- 할 일
  1. Lighthouse로 baseline 기록 (같은 조건에서 3회 측정 권장).
  2. 이미지, 폰트 로딩, 번들 크기, 불필요한 리렌더링 중 2가지 개선.
  3. after 기록과 개선 이유.
- 평가: P, R, E, L

### Day 13. 접근성 점검
- 목표: 키보드·대비·스크린리더 기본 흐름을 확인한다.
- 할 일
  1. 키보드만으로 전체 화면 사용.
  2. 대비 재확인, 포커스 표시 누락 확인.
  3. (맥이라면) VoiceOver로 버튼·폼·모달 흐름 확인 후 문제 기록.
- 평가: X, T, R, E, L

### Day 14. 개선 화면 + 사이클 회고
- 목표: 정답지를 넘어 내 판단으로 개선해 본다.
- 할 일
  1. 원본과 다르게 개선한 CTA 화면 1개 + 개선 근거.
  2. 비교 보드 v2 정리.
  3. 사이클 회고, 사이클 2(실제 웹 서비스 측정) 계획.
- 평가: F, M, R, E, L
