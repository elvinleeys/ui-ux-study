# 과제 제출

## 절차
1. `npm run check`를 실행하고 결과를 보여 준다. 실패해도 제출은 가능하지만, 실패 내용을 제출서에 그대로 적는다.
2. `submissions/day-NN/` 폴더를 만들고 `templates/submission.md`를 복사해 `submission.md`를 만든다.
3. 이 세션에서 실제로 한 일을 근거로 아래 칸의 **초안**을 채운다.
   - 2. 한 일, 3. 산출물 위치, 5. 막혔던 점과 해결
   - 6. 핵심 프롬프트: 사용자가 지시를 바꾼 지점 2~4개 (수정 전 → 수정 후 → 이유)
4. 아래 칸은 비워 두고 사용자가 직접 채우게 한다.
   - 4. 셀프 체크 (사용자가 직접 확인한 것만 체크)
   - 7. 사용량 메모, 8. 리뷰어에게 봐 달라고 할 것
5. 사용자가 확인·수정을 마치면 커밋을 제안한다.
   - 커밋 메시지: `submit: Day NN <주제>`
   - `git push -u origin day-NN-<주제>`
   - GitHub에서 PR 생성. 제목 `[Day NN] <주제>`, 본문에 submission.md 내용. (`gh` CLI가 있으면 `gh pr create` 제안, 없으면 웹에서 직접)
6. `docs/progress.md` 상태를 `제출됨`으로 바꾼다.
7. 마지막 안내: "이 세션은 여기서 마치고, 새 터미널(또는 /clear 후)에서 `/ui-review NN`을 실행하세요."

## 지킬 것
- 점수나 통과 여부를 말하지 않는다.
- 하지 않은 일을 한 것처럼 쓰지 않는다.
